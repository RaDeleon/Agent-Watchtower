# Claude Watchtower 0.10.0

Stage 9: onboarding. One command takes a fresh checkout to a working dashboard. The database schema is unchanged (`CC_SCHEMA_VERSION` 11, `WT_SCHEMA_VERSION` 3).

**`watchtower setup`.** Run `./bin/watchtower setup` from the checkout. It checks the requirements and prints what it found, then asks a few questions before it writes anything: wire the status line, enable each detected source (one question per source), read existing history now, put `watchtower` on your PATH, and open the dashboard. It shows a `diff -u` of `settings.json` and asks "Apply?", installs, checks the written file against the preview, and runs the steps you chose. It ends with the exact command for anything you declined. On an existing install, Enter at every question gives exactly the install you already have. A run without a terminal installs capture only, and `--yes` takes the defaults shown. Flags (`--[no-]status-line`, `--[no-]backfill`, `--[no-]link`, `--[no-]open`, `--disable <id,...>`) answer a question ahead of time.

**`capture/install.sh`.** Two new flags. `--dry-run` prints the `settings.json` the install would write and writes nothing. `--status-line` wires `watchtower-snapshot.sh` as the status line, only when Claude Code has none; an existing status line is never edited. The installer now requires `sqlite3`, as it already required `jq`, and says so before it changes anything.

**Config.** `watchtower.config.json` is read from the current directory, else from the checkout, so the command works from anywhere once it is on your PATH.

**Backfilled history.** Tokens, cost and the Usage Profile cover your past history. Active hours, levels and quests start with your first session after the install, because archived transcripts do not recreate hook events.

Requires macOS or Linux with `bash`, `jq` and the `sqlite3` CLI, and Node.js 22.18 or newer with default TypeScript stripping. This is a preview: measurements and page layouts may still change between minor versions.
