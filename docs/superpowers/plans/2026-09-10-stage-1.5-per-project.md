# Stage 1.5 — Per-Project Hour Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Break Watchtower's existing active/window/prompt/cost figures out per project, all-time and over the last 30 days, without adding a second activity model.

**Architecture:** Capture records the git toplevel path it already computes and throws away. `rollup.sh` resolves any cwd it has not seen into a durable `claude_project_paths` cache, then writes one `claude_project_rollups` row per `(project_key, day)` inside the existing rebuild transaction. TypeScript sums rows and applies display grouping. No model math moves out of `capture/rollup.sh`.

**Tech Stack:** bash 3.2 (what `/usr/bin/env bash` resolves to on stock macOS), sqlite3 3.51, jq 1.8, TypeScript 5, vitest 4, Node 22.

**Spec:** `docs/superpowers/specs/2026-09-10-stage-1.5-per-project.md`

## Global Constraints

Copied verbatim from the spec and from Stage 1's still-binding constraints. Every task's requirements implicitly include this section.

- **The activity model exists in exactly one place:** `capture/rollup.sh`, in the `_act` CTE. No TypeScript reimplementation, ever. `tests/capture-scripts.test.ts` fails if `MIN(gap,` appears in any other file.
- **Activity model constants:** think cap `300` seconds, work sanity cap `14400` seconds. `MIN(gap, 300)` appears exactly twice in `rollup.sh` and `MIN(gap, 14400)` exactly twice. A test pins both counts. **This stage must not change either count.**
- **Session duration is `window_s`**, never `ended_at - started_at`. Never read `claude_sessions.duration_ms`.
- **A session is attributed to its local START day**, whole. Pinned by the `crosses-midnight` fixture.
- **Capture scripts must never break Claude Code.** `hook.sh` and `snapshot.sh` exit 0 silently on any missing dependency or DB error, writing nothing to stdout, always.
- **This stage must not change lifetime hours or rank.** `claude_daily_rollups` and `claude_rank_progress` are read-only to this work. If a task changes a number in either, the task is wrong.
- **Never run `install.sh` without `CLAUDE_DIR`** pointed at a temp dir.
- **Never test against the live DB.** Copy with `sqlite3 .backup` (never `cp` — it is WAL) and point `THEONE_DB_PATH` at the copy.
- **Bash quoting is verified under `/bin/bash`, not the shell your tool happens to use.** `${v//"'"/"''"}` works in zsh and emits the quote characters as data in bash 3.2. Use `cc_sqlstr`; never hand-roll SQL quoting.
- **Fixtures fail loudly.** New fixture SQL goes through `fx_sql`, never `cc_sql` — `cc_sql` swallows errors and yields an empty fixture DB with a green assertion.
- **Reserved project keys** are `(unfiled)` and `(excluded)`. Parenthesised so they cannot collide with a real toplevel path, which is always absolute.

- [ ] **Step 3: Add `cc_project_path` to `capture/lib.sh`**

Place it directly above `cc_repo`, which already runs this exact `git` call:

```bash
# Git toplevel PATH for a cwd, or empty when the cwd is not in a repo.
# Deliberately NOT basename'd: the PATH is the project key, the basename is only
# how it is displayed, so two same-named repos under different parents stay
# distinct rows. Empty is meaningful and means Unfiled.
# cc_repo below runs this same git call and throws the path away, so recording
# it costs no additional subprocess on the hook path.
cc_project_path() {
  local d="$1"
  [ -z "$d" ] && { printf ''; return 0; }
  git -C "$d" --no-optional-locks rev-parse --show-toplevel 2>/dev/null || printf ''
}
```

- [ ] **Step 3: Add `cc_is_excluded` to `capture/lib.sh`**

```bash
# cc_is_excluded <cwd> [pattern...] -> exit 0 when cwd matches any pattern.
# A pattern is either a path PREFIX (matches the dir and everything under it) or
# a glob. Matching is bash `case` globbing, deliberately not a regex engine.
# The trailing-slash test is what stops /a/bc matching the prefix /a/b.
cc_is_excluded() {
  local d="$1"; shift
  local p
  for p in "$@"; do
    [ -z "$p" ] && continue
    case "$d" in
      "$p"|"$p"/*) return 0 ;;
      $p) return 0 ;;
    esac
  done
  return 1
}
```

The unquoted `$p` on the third branch is deliberate: that is what makes the glob patterns expand. The quoted branches above it handle the exact and prefix cases.

-- cwd -> git toplevel, resolved once and KEPT. A row here is a durable answer to
-- a question the filesystem may stop being able to answer: a project deleted
-- next week keeps the attribution it had this week. Never DELETEd by the
-- rebuild -- unlike the rollup tables, this one is not regenerable.

  project_path  TEXT,              -- NULL: resolved, and not a repo -> (unfiled)
  resolved_at   INTEGER NOT NULL,
  source        TEXT NOT NULL      -- 'git' | 'gone' | 'excluded'
);

- [ ] **Step 9: Add the resolution step to `capture/rollup.sh`**

Insert after `DB="$(cc_db_path)"` and **before** the `sqlite3 ... <<'SQL'` heredoc:

```bash
# ---- resolve cwd -> project, once per cwd, cached forever --------------------
# Runs in BASH, above the SQL, because resolving a cwd means `git rev-parse` and
# SQL cannot shell out. Bounded by NEW cwds, not total: the steady state is one
# SELECT returning nothing. The cache is never rebuilt -- see cc_schema_sql.
#
# WATCHTOWER_EXCLUDE_PATHS is a newline-separated list, supplied by the caller
# (lib/config.ts owns the defaults). Empty means exclude nothing.
_resolve_new_cwds() {
  local unresolved cwd proj now src
  unresolved="$(cc_sql_val "SELECT DISTINCT cwd FROM claude_events
                            WHERE cwd IS NOT NULL AND cwd <> ''
                              AND cwd NOT IN (SELECT cwd FROM claude_project_paths);")"
  [ -z "$unresolved" ] && return 0
  now="$(cc_now)"
  while IFS= read -r cwd; do
    [ -z "$cwd" ] && continue
    # shellcheck disable=SC2086
    if cc_is_excluded "$cwd" $WATCHTOWER_EXCLUDE_PATHS; then
      src="excluded"; proj=""
    elif [ ! -d "$cwd" ]; then
      src="gone"; proj=""
    else
      src="git"; proj="$(cc_project_path "$cwd")"
    fi
    cc_sql "INSERT OR IGNORE INTO claude_project_paths (cwd, project_path, resolved_at, source)
            VALUES ($(cc_sqlstr "$cwd"), $(cc_sqlstr "$proj"), $now, $(cc_sqlstr "$src"));"
  done <<EOF
$unresolved
EOF
}
_resolve_new_cwds
```

`cc_sqlstr ""` yields `NULL`, which is exactly what `project_path` should hold for the `excluded` and `gone` cases and for a real directory that is not a repo.

`INSERT OR IGNORE`, not `INSERT`: two rollups racing on `SessionEnd` must not fail on the primary key.

- [ ] **Step 5: Build `_pk` FIRST, above `_act`**

`_pk` maps cwd to project key. It must exist **before** `_act`, because `_act`
has to aggregate by project key, not by cwd. Insert immediately after
`BEGIN IMMEDIATE;` and before `DROP TABLE IF EXISTS _act;`:

```sql
DROP TABLE IF EXISTS _pk;
-- cwd -> project_key, the ONLY place the reserved keys are minted. Parenthesised
-- so they cannot collide with a real toplevel, which is always absolute.
-- LEFT JOIN, not INNER: a cwd the resolution step has not seen must still land
-- somewhere, and (unfiled) is the honest answer.
CREATE TEMP TABLE _pk AS
SELECT e.cwd,
       CASE
         WHEN p.source = 'excluded'   THEN '(excluded)'
         WHEN p.project_path IS NULL  THEN '(unfiled)'
         ELSE p.project_path
       END AS project_key
FROM (SELECT DISTINCT cwd FROM claude_events WHERE cwd IS NOT NULL AND cwd <> '') e
LEFT JOIN claude_project_paths p ON p.cwd = e.cwd;
CREATE INDEX IF NOT EXISTS _pk_cwd ON _pk(cwd);
```

- [ ] **Step 6: Aggregate `_act` by project key, NOT by cwd**

**This is the step to get right.** A repo and a subdirectory of that repo are two
different cwds resolving to the **same** project key — and 15 of 75 real cwds are
subdirectories. Grouping by `cwd` would give one session two rows under one
project, `SUM(is_dom)` would count it twice, and the reconciliation identity in
Step 2 would fail on exactly the shape that is most common.

In the `ev` CTE, join `_pk` and select the key and the row id:

```sql
WITH ev AS (
  SELECT e.session_id, e.ts, e.hook_event_name AS e, e.id,
         COALESCE(k.project_key, '(unfiled)') AS project_key,
         e.ts - LAG(e.ts) OVER (PARTITION BY e.session_id ORDER BY e.ts, e.id) AS gap,
         MAX(CASE WHEN e.hook_event_name = 'UserPromptSubmit' THEN e.ts ELSE 0 END)
           OVER (PARTITION BY e.session_id ORDER BY e.ts, e.id
                 ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS last_work,
         MAX(CASE WHEN e.hook_event_name IN ('Stop','SessionStart') THEN e.ts ELSE 0 END)
           OVER (PARTITION BY e.session_id ORDER BY e.ts, e.id
                 ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS last_idle
  FROM claude_events e
  LEFT JOIN _pk k ON k.cwd = e.cwd
  WHERE e.session_id IS NOT NULL
    AND e.hook_event_name NOT IN ('LauncherStart','LauncherEnd')
)
```

The gap is `ts - LAG(ts)`, so it **ends** at the current row — `ev.project_key` is
therefore already the key of the event that ends the gap, which is the
attribution rule exactly. No extra window function is needed.

Add `project_key` and `MAX(id) AS last_id` to `_act`'s SELECT list, and change its
final line to:

```sql
FROM ev GROUP BY session_id, project_key;
```

`last_id` is the deterministic tie-break for `_pdom` in Step 8.

The constants `MIN(gap, 300)` and `MIN(gap, 14400)` must still appear exactly
twice each. Run `npx vitest run tests/capture-scripts.test.ts -t "exactly as many times"` to confirm.

- [ ] **Step 8: Add `_pdom` — the dominant project per session**

```sql
DROP TABLE IF EXISTS _pdom;
-- The project a session's SCALARS belong to: tokens, cost, prompts, sessions
-- count. Time splits per gap, scalars do not -- a session counted 1 in two rows
-- makes SUM(sessions_count) exceed the daily rollup, and duplicating the latest
-- snapshot's tokens into both rows is the same fan-out that once doubled every
-- daily aggregate. 20 of 2,478 sessions touch more than one cwd.
-- Ties break by the session's LAST event id -- the same ordering discipline _act
-- uses, because ORDER BY ts alone leaves ties to an order SQLite does not promise.
CREATE TEMP TABLE _pdom AS
SELECT session_id, project_key FROM (
  SELECT session_id, project_key,
         ROW_NUMBER() OVER (PARTITION BY session_id
                            ORDER BY active_s DESC, last_id DESC) AS rn
  FROM _act
)
WHERE rn = 1;
```

`_act` is already one row per `(session_id, project_key)` after Step 6, so this
needs no further aggregation.

```sql
DELETE FROM claude_project_rollups;
INSERT INTO claude_project_rollups (
  project_key, day, display_name,
  active_ms, window_ms, idle_ms, sessions_count, prompts, compacts, clears, subagents,
  tokens_in, tokens_out, tokens_cache_read, tokens_cache_creation, cost_usd,

  CAST(SUM(t.window_s) * 1000 AS INTEGER),
  CAST(SUM(t.window_s - t.active_s) * 1000 AS INTEGER),
  SUM(t.is_dom),
  SUM(t.is_dom * COALESCE(t.prompts,0)),
  SUM(t.is_dom * COALESCE(t.compacts,0)),
  SUM(t.is_dom * CASE WHEN t.source='clear' THEN 1 ELSE 0 END),
  SUM(t.is_dom * COALESCE(t.subagents,0)),
  SUM(t.is_dom * t.tin), SUM(t.is_dom * t.tout),
  SUM(t.is_dom * t.tcr), SUM(t.is_dom * t.tcw),
  SUM(t.is_dom * t.cost),
  MAX(t.peakctx),
  AVG(t.avgctx),
  strftime('%s','now')
FROM (
  SELECT a.project_key, sx.day, a.session_id, a.active_s, a.window_s,
         sx.prompts, sx.compacts, sx.subagents, sx.source,
         sx.tin, sx.tout, sx.tcr, sx.tcw, sx.cost, sx.peakctx, sx.avgctx,

  FROM _act a
  JOIN _sx   sx ON sx.session_id = a.session_id
  LEFT JOIN _pdom d ON d.session_id = a.session_id
) t
GROUP BY t.project_key, t.day;
```

`is_dom` is the whole mechanism: multiplying every session-level scalar by it means each scalar lands in exactly one project row per session, while `active_s`/`window_s` sum across all of them.

```sql
-- models_json: {"model": {"sessions":N,"thinking":N,"effort":{"high":N,...}}}
-- DOMINANT sessions only, so a session split across projects contributes its
-- model to exactly one of them -- the same rule as every other scalar.
DROP TABLE IF EXISTS _pmodel;
CREATE TEMP TABLE _pmodel AS
SELECT a.project_key, sx.day, sx.model, sx.effort,
       COUNT(DISTINCT a.session_id) AS sessions,
       SUM(sx.thinking)             AS thinking
FROM _act a
JOIN _sx   sx ON sx.session_id = a.session_id
JOIN _pdom d  ON d.session_id  = a.session_id AND d.project_key = a.project_key
GROUP BY a.project_key, sx.day, sx.model, sx.effort;

UPDATE claude_project_rollups AS r SET models_json = (
  SELECT json_group_object(m.model, json_object(
           'sessions', m.sessions,
           'thinking', m.thinking,
           'effort',   m.effort_json))
  FROM (SELECT project_key, day, model,
               SUM(sessions) AS sessions, SUM(thinking) AS thinking,
               json_group_object(effort, sessions) AS effort_json
        FROM _pmodel GROUP BY project_key, day, model) m
  WHERE m.project_key = r.project_key AND m.day = r.day
);
```

`COUNT(DISTINCT a.session_id)`, not `COUNT(*)`: after Step 6 `_act` is one row per
`(session, project_key)`, but keeping the DISTINCT makes the intent explicit and
survives anyone re-widening that grouping later.

```typescript
import { execFileSync } from "node:child_process";

export interface ProjectRow {
  key: string;
  label: string;
  activeHours: number;
  windowHours: number;
  sessions: number;
  prompts: number;
  costUsd: number;
  peakContextPct: number;
}

interface RawRow {
  project_key: string; display_name: string | null;
  active_ms: number; window_ms: number;
  sessions_count: number; prompts: number;
  cost_usd: number; peak_context_pct: number;
}

/**
 * Read per-project rows for a range.
 *
 * SUMs rows that capture/rollup.sh already computed. No gap logic, no caps, no
 * day bucketing -- the activity model lives in capture/rollup.sh and nowhere
 * else, and tests/capture-scripts.test.ts fails if a model constant appears here.
 *
 * (excluded) is filtered out for display. It exists in the table so that every
 * second the daily rollup counts is findable in some per-project row, which is
 * what makes the reconciliation test unconditional.
 */
export function readProjectRows(dbPath: string, range: "all" | "30d"): ProjectRow[] {
  const where =
    range === "30d" ? `WHERE day >= date('now','localtime','-29 days')` : "";
  const sql = `SELECT project_key, display_name,
      SUM(active_ms) AS active_ms, SUM(window_ms) AS window_ms,
      SUM(sessions_count) AS sessions_count, SUM(prompts) AS prompts,
      SUM(cost_usd) AS cost_usd, MAX(peak_context_pct) AS peak_context_pct
    FROM claude_project_rollups
    ${where}
    GROUP BY project_key ORDER BY active_ms DESC;`;
  const out = execFileSync("sqlite3", ["-json", dbPath, sql], { encoding: "utf8" });
  const raw: RawRow[] = out.trim() === "" ? [] : JSON.parse(out);
  return raw
    .filter((r) => r.project_key !== "(excluded)")
    .map((r) => ({
      key: r.project_key,
      label: r.display_name ?? r.project_key,
      activeHours: r.active_ms / 3_600_000,
      windowHours: r.window_ms / 3_600_000,
      sessions: r.sessions_count,
      prompts: r.prompts,
      costUsd: r.cost_usd,
      peakContextPct: r.peak_context_pct,
    }));
}

/**
 * Collapse grouped projects into one labelled row. Pure labelling: it never
 * touches the stored rows, so a group can be edited without a rebuild.
 * A project named in two groups joins the FIRST only -- otherwise its hours
 * would appear twice in one table and the column would not sum to the total.
 */
export function applyGroups(
  rows: ProjectRow[],
  groups: Record<string, string[]>,
): ProjectRow[] {
  const labelOf = new Map<string, string>();
  for (const [label, members] of Object.entries(groups)) {
    for (const m of members) if (!labelOf.has(m)) labelOf.set(m, label);
  }
  const out: ProjectRow[] = [];
  const byLabel = new Map<string, ProjectRow>();
  for (const r of rows) {
    const label = labelOf.get(r.label);
    if (label === undefined) { out.push(r); continue; }
    const acc = byLabel.get(label);
    if (acc === undefined) {
      byLabel.set(label, { ...r, key: `(group)${label}`, label });
    } else {
      acc.activeHours += r.activeHours;
      acc.windowHours += r.windowHours;
      acc.sessions += r.sessions;
      acc.prompts += r.prompts;
      acc.costUsd += r.costUsd;
      acc.peakContextPct = Math.max(acc.peakContextPct, r.peakContextPct);
    }
  }
  return [...out, ...byLabel.values()].sort((a, b) => b.activeHours - a.activeHours);
}
```
