## 2. A correction to the architecture document

The architecture doc (§7) says `schemaVersion` goes to **5**, bumped in both
declared places — `CC_SCHEMA_VERSION` in `capture/lib.sh` and `schemaVersion` in
`lib/config.ts`.

**That conflicts with decision 8**, which defers the `capture/` move so that
*"Stage 3 touches nothing under `~/.claude` at all."* `capture/lib.sh` is
installed as `~/.claude/cc-track-lib.sh`. Adding `wt_*` tables to `cc_schema_sql`
would require editing it, bumping `CC_SCHEMA_VERSION`, **and reinstalling** — or
the marker short-circuits `cc_init_db`'s fast path and the tables never arrive.

That failure mode is not hypothetical. `capture/lib.sh:298` records it happening:
Stage 1.5 added two tables under an unchanged version 2, `rollup.sh` then aborted
its whole transaction on every v2 install, and because it runs `--quiet` from the
`SessionEnd` hook, **daily tracking went stale in silence.**

### Resolution: schema ownership splits along layer ownership

| Owner | Tables | Version constant | Marker |
|---|---|---|---|
| `capture/lib.sh` | `claude_*` | `CC_SCHEMA_VERSION` — **stays 4** | `.schema-v4` |
| Watchtower core (TS) | `wt_*` | `WT_SCHEMA_VERSION` — **new, starts 1** | `.wt-schema-v1` |

Consequences, all good:

- **Stage 3 changes no file under `~/.claude` and requires no reinstall.** Decision
  8 holds literally, not approximately.
- `lib/config.ts`'s `schemaVersion` stays **4** and the existing pinning test
  passes unchanged.
- Two markers in one directory is safe **only because the names differ**. The
  "two databases in one directory share a marker" trap (bitten three times) is
  about two *databases*; this is two *namespaces* in one database, with distinct
  marker names. A test asserts the names cannot collide.
- Core's migration is a separate, ordinary, loud-on-failure path. It is **not** on
  the hook path, so unlike `cc_init_db` it may fail loudly — and must.

**`WT_SCHEMA_VERSION` is declared twice** (`lib/core/schema.ts` and the marker
name it generates) for the same reason `CC_SCHEMA_VERSION` is. A test pins them.

## 3A. Foundation

### 3A.1 Record envelope — `lib/core/records.ts`

As the architecture §5, implemented verbatim. Normative rules:

- `timestamp` and `observedAt` are **RFC3339 with an explicit offset**. Adapters
  convert at the boundary; nothing downstream parses a naked local time.
- **A metric the source does not expose is absent, not `0`.** `metrics` is a
  sparse map. `undefined` and `0` are different facts and the schema must keep
  them different.
- `sourceRecordId` is unique **within a source**, never globally.
- `sessionId` is **source-local**. Canonical ids come from `wt_sessions`.

### 3A.2 Adapter contract — `lib/core/adapters.ts`

As architecture §4. `detect()` and `health()` **must not throw**; both return a
state. A missing source is normal.

### 3A.3 Schema — `lib/core/schema.ts`, `WT_SCHEMA_VERSION = 1`

```sql
CREATE TABLE IF NOT EXISTS wt_sources (
  source          TEXT PRIMARY KEY,
  adapter_version INTEGER NOT NULL,
  enabled         INTEGER NOT NULL DEFAULT 1,
  capabilities    TEXT NOT NULL DEFAULT '[]',   -- JSON
  authority       TEXT NOT NULL DEFAULT '[]',   -- JSON: [{kind,metrics[]}]
  first_seen      INTEGER,
  updated_at      INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS wt_ingest_state (
  source            TEXT PRIMARY KEY,
  cursor            TEXT,
  last_run_at       INTEGER,
  last_ok_at        INTEGER,
  records_ingested  INTEGER NOT NULL DEFAULT 0,
  metrics_rejected  INTEGER NOT NULL DEFAULT 0,   -- authority violations
  records_malformed INTEGER NOT NULL DEFAULT 0,
  health            TEXT NOT NULL DEFAULT 'unknown',
  last_error        TEXT
);

CREATE TABLE IF NOT EXISTS wt_sessions (
  canonical_id  TEXT PRIMARY KEY,
  first_source  TEXT NOT NULL,
  started_at    INTEGER,
  ended_at      INTEGER,
  project       TEXT, repo TEXT, branch TEXT,
  agent         TEXT, model TEXT,
  updated_at    INTEGER NOT NULL
);

-- Per-source completeness. Required by §14 decision 5: a live session has
-- provenance from one source and no usage yet from another, and that is NOT
-- the same fact as "zero usage".
CREATE TABLE IF NOT EXISTS wt_session_state (
  canonical_id TEXT NOT NULL,
  source       TEXT NOT NULL,
  state        TEXT NOT NULL,   -- 'pending' | 'complete'
  updated_at   INTEGER NOT NULL,
  PRIMARY KEY (canonical_id, source)
);

CREATE TABLE IF NOT EXISTS wt_links (
  source          TEXT NOT NULL,
  source_local_id TEXT NOT NULL,
  link_kind       TEXT NOT NULL,   -- 'same_session'|'produced_commit'|'touched_file'
  canonical_id    TEXT NOT NULL,
  confidence      TEXT NOT NULL,   -- 'exact' | 'inferred'  (only 'exact' written)
  evidence        TEXT,            -- the join key actually used, for audit
  created_at      INTEGER NOT NULL,
  PRIMARY KEY (source, source_local_id, link_kind)
);

-- Typed common path (decision 1: hybrid, biased typed)
CREATE TABLE IF NOT EXISTS wt_requests (
  source          TEXT NOT NULL,
  source_record_id TEXT NOT NULL,
  canonical_id    TEXT,
  ts              INTEGER NOT NULL,
  observed_at     INTEGER,
  model           TEXT, agent TEXT,
  project         TEXT, repo TEXT, branch TEXT,
  is_subagent     INTEGER,
  tokens_in       INTEGER, tokens_out INTEGER,
  tokens_cache_read INTEGER, tokens_cache_creation INTEGER,
  cost_usd        REAL,
  error_status    TEXT,
  PRIMARY KEY (source, source_record_id)
);

-- Tall overflow for adapter-specific metrics (decision 1)
CREATE TABLE IF NOT EXISTS wt_usage (
  source          TEXT NOT NULL,
  source_record_id TEXT NOT NULL,
  canonical_id    TEXT,
  ts              INTEGER NOT NULL,
  metric          TEXT NOT NULL,
  value           REAL NOT NULL,
  PRIMARY KEY (source, source_record_id, metric)
);

CREATE TABLE IF NOT EXISTS wt_events (
  source TEXT NOT NULL, source_record_id TEXT NOT NULL,
  canonical_id TEXT, ts INTEGER NOT NULL, kind TEXT NOT NULL,
  project TEXT, repo TEXT, branch TEXT,
  dimensions TEXT, metadata TEXT,
  PRIMARY KEY (source, source_record_id)
);

CREATE TABLE IF NOT EXISTS wt_tools (
  source TEXT NOT NULL, source_record_id TEXT NOT NULL,
  canonical_id TEXT, ts INTEGER NOT NULL,
  tool_name TEXT NOT NULL, tool_kind TEXT,   -- 'mcp'|'skill'|'plugin'|'builtin'
  server TEXT, status TEXT,
  PRIMARY KEY (source, source_record_id)
);

CREATE TABLE IF NOT EXISTS wt_metrics (
  source TEXT NOT NULL, ts INTEGER NOT NULL,
  metric TEXT NOT NULL, value REAL NOT NULL,
  dimensions TEXT,
  PRIMARY KEY (source, ts, metric)
);
```

**Every `wt_*` write is an upsert on its primary key.** That is what makes ingest
idempotent and cursors advisory — the same argument that already makes
`claude_ingest_cursor` advisory, generalized to every source.

### 3A.4 Authority enforcement — `lib/core/ingest.ts`

The load-bearing rule (architecture §1, decision 9):

1. Resolve the record's `(kind, metric)` pairs against `wt_sources.authority`.
2. Authoritative → written.
3. Non-authoritative → **rejected, `wt_ingest_state.metrics_rejected` incremented,
   surfaced in the Sources view.** Never written, never averaged, never summed.
4. Dimensions, links and metadata from a non-authoritative source are **accepted**
   — that is enrichment, and it is the point.

**A rejection is not an error.** Atlas legitimately carries `token_totals`; being
rejected is the system working. The counter exists so the *volume* is visible, not
to signal a fault.

### 3A.5 Discovery — `lib/core/discovery.ts`

Per architecture §7. Atlas's scan is bounded to configured project roots at fixed
depth with cached results; every other probe is a `stat` or a short-timeout HTTP
call. `detect()` never throws; missing is a state.

### 3A.6 NDJSON boundary — `lib/adapters/external/`

```bash
some-adapter | watchtower ingest --stdin --source my-agent
```

- one `WatchtowerRecord` per line
- unknown `kind` → `custom`, preserved in `wt_metrics`, never dropped
- malformed line → counted in `records_malformed`, reported, **stream continues**
- `--source` must be pre-registered in config; a typo cannot mint a source
- external records are `enrichment` unless config grants authority (decision 12)

### 3A.7 Regression baseline — frozen here (decision 7)

`tests/regression/claude-baseline.json`, generated from the **current**
implementation over the existing fixture DBs and committed, covering: active,
window, idle, sessions, prompts, tokens in/out/cache read/cache creation,
cost, compacts, clears, subagents, per-project rows, hygiene, rank.

Every later stage asserts **exact equality**. Cost compares to a fixed epsilon for
IEEE-754 round-off only, matching the existing 3.6e-15 precedent. Nothing else is
approximate.

## 3B. Claude adapter

### 3B.1 It is a projection

`capture/*.sh` **do not change.** The adapter reads `claude_*` and writes `wt_*`.
It invents no number; every value is copied. That is what keeps it out of the
model-math prohibition.

### 3B.2 Mapping

| `wt_` target | Source | Rule |
|---|---|---|
| `wt_requests` | `claude_requests` | 1:1. `is_subagent ← is_sidechain`. `source_record_id ← request_id`. |
| `wt_sessions` | `claude_sessions` | `canonical_id` minted; `session_id` recorded in `wt_links` as `exact`. |
| `wt_events` | `claude_events` | `kind = 'event'`; the hook name goes to `dimensions.hook_event_name`. |
| `wt_tools` | `claude_requests` attribution columns | `attribution_skill` / `_mcp_server` / `_mcp_tool` / `_plugin`. |
| `wt_usage` | `claude_status_snapshots` | **`MAX` per `session_id`**, lines added/removed only. |

**Why the hook name is a dimension, not the kind.** `RECORD_KINDS` is a closed
set the envelope validator enforces, and `SessionStart` is not in it. Widening
that set per source is exactly the "force every source into one shape" failure
the taxonomy exists to avoid: `hook_event_name` is Claude-specific vocabulary,
and Claude-specific vocabulary belongs in `dimensions`.

**Claude is authoritative for** `request.{tokens_in,tokens_out,tokens_cache_read,tokens_cache_creation}`
and `session.{cost_usd,lines_added,lines_removed}`.

**Cost is a SESSION metric, not a request metric.** `claude_requests` has no
`cost_usd` column; cost is observed only as `claude_status_snapshots.total_cost_usd`,
a cumulative per-session counter that `rollup.sh:423` reads as `MAX(...) GROUP BY
session_id`. Claiming cost_usd as a per-request authority would claim ownership of
a metric no Claude record can ever carry, and would silently block a future source
that can.

### 3B.3 Invariants carried into the adapter

These are existing CLAUDE.md invariants restated as adapter rules, because the
adapter is a new place each could be violated:

1. **Tokens come from `claude_requests`, never snapshots.** The adapter must not
   read a token column from `claude_status_snapshots` at all.
2. **Snapshot counters are `MAX`-per-session, never `SUM`.** Lines added/removed
   only; measured overcount if summed is 281.7×.
3. **Never aggregate through `claude_sessions`.** 22.4% of requests have no
   session row. The adapter reads `claude_requests` directly and leaves
   `canonical_id` NULL where no session exists, rather than dropping the row.
4. **Never read `claude_sessions.duration_ms`.** `wt_sessions` carries
   `started_at`/`ended_at` for identity only. **Duration is not projected** — the
   only valid duration is `window_s` summed per gap by `rollup.sh`, and it stays
   in `claude_*`.
5. **No `MIN(gap,`** anywhere in `lib/`. Carriers guard extended.

### 3B.4 Session completeness

A Claude session with a transcript but no ingested requests is
`wt_session_state = 'pending'`, not zero usage. Measured 2026-09-14: 100 live
sessions have this shape, including the session that produced this spec.

### 3B.5 Regression gate

3B is not done until `claude-baseline.json` passes **exactly**, and a planted
perturbation turns exactly one test red.

- **Absent `sources` means Claude enabled.** No existing config breaks.
- `host` rejects any non-loopback value, loudly.
- Path resolution: `WATCHTOWER_DB_PATH` → `THEONE_DB_PATH` *(deprecated alias,
  still honoured)* → explicit config → existing `~/.theone/...` →
  `~/.watchtower/watchtower.sqlite` for a fresh install only. **`capture/lib.sh`
  resolves this identically** — it is the writer, and a split from the reader is
  silent by construction.

## 5. Testing

Fixture-driven, per repo convention: real scripts against fixture DBs, `TZ=UTC`
pinned, fixtures encoding values through `lib.sh`'s own encoders.

**Mutation checks — each planted and watched turn exactly one test red:**

| # | Defect | Guard |
|---|---|---|
| 1 | `SUM` a snapshot counter instead of `MAX`-per-session | 281.7× overcount test |
| 2 | Project a token column from snapshots | forbidden-source test |
| 3 | Join requests through `claude_sessions` | ~22.4% row-loss test |
| 4 | Accept a non-authoritative metric | Atlas `token_totals` appears in `wt_requests` |
| 5 | Write an `inferred` link | confidence-is-always-exact test |
| 6 | Coalesce a NULL rate limit to 0 | "no reading" test |
| 7 | Clamp a rate limit to 100 | 108% test |
| 8 | `MIN(gap,` in `lib/core`, `lib/adapters`, `lib/read`, `lib/render` | carriers guard |
| 9 | Bind the server to `0.0.0.0` | loopback test |
| 10 | Perturb one regression baseline number | exactly one baseline test |
| 11 | Collide `.schema-v4` and `.wt-schema-v1` marker names | marker-distinctness test |
| 12 | Read an Atlas prompt-text column | allowlist test |

Guards 4, 5, 11 and 12 are new to this stage and guard decisions 9, 13, §2 and 10
respectively.
